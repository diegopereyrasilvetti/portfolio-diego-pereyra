Gestión de stock

React · Vite · Node.js · Express · Supabase · PostgreSQL · Tailwind CSS · Zod · Helmet

El problema

Una empresa chica necesita saber qué tiene, qué vendió y cuándo reponer. Cuando eso vive en planillas sueltas, los datos se desactualizan y los faltantes se descubren tarde. Es un problema que conozco de mi trabajo en depósito.

Qué hace

  • Inventario, catálogo de productos, proveedores, ventas, gastos y balances en un solo panel.
  • Alertas cuando un producto queda por debajo de su mínimo o se agota.
  • Acceso por invitación: el administrador crea las cuentas y cada una tiene un rol (administrador o usuario).

Decisiones técnicas

  • Operaciones "todo o nada": vender, ajustar stock o eliminar una venta se ejecuta completo o no se ejecuta, y cada cambio queda en un historial de movimientos.
  • El servidor calcula los precios: el total de una venta sale de los datos de la base, nunca del navegador.
  • Seguridad en la base de datos: PostgreSQL con seguridad por fila (RLS) decide quién puede hacer qué, y la clave secreta de Supabase solo vive en el servidor.
  • Reglas de negocio protegidas: nadie puede quitarse a sí mismo el rol de administrador y la empresa nunca se queda sin un administrador activo.

Tecnologías

React, Vite y Tailwind CSS en la web; Node.js con Express, Zod y Helmet en la API; Supabase Auth y PostgreSQL para cuentas y datos; publicado en Vercel.

E-commerce · Kodex Tech Store

React · Vite · Node.js · Express · Supabase · PostgreSQL · Tailwind CSS · Zod · Helmet

El objetivo

Construir una tienda de hardware completa, de punta a punta: catálogo, buscador, carrito, cuentas de usuario y una API propia. Es un proyecto de portfolio, así que no realiza ventas reales.

Qué hace

  • 10 categorías con orden por precio y una página por producto con descuento por transferencia y cuotas.
  • Buscador que sugiere productos mientras se escribe, sin importar tildes ni mayúsculas.
  • Carrito que se mantiene al recargar la página.
  • Calculadora de cuello de botella entre procesador y placa de video.
  • Cuentas con confirmación por email, recuperación de contraseña y direcciones de envío guardadas.

Decisiones técnicas

  • API propia: Node.js y Express con validación de datos (Zod), cabeceras de seguridad (Helmet), CORS y límite de solicitudes.
  • Privacidad por usuario: con seguridad por fila (RLS), cada persona solo puede ver y modificar sus propios datos.
  • Pruebas automáticas: 185 pruebas (43 del frontend y 142 del servidor, con ~99 % de cobertura en el servidor) que corren en GitHub Actions en cada push.
  • Responsive y accesible: revisado en 9 anchos de pantalla, de 320 a 1024 px, navegable con teclado y con respeto a "reducir animaciones".

Tecnologías

React, Vite y Tailwind CSS en la web; Node.js con Express, Zod y Helmet en la API; Supabase Auth y PostgreSQL para cuentas y datos; Vitest y Supertest para las pruebas, que corren en GitHub Actions.

Sitio web de hotel

React · Vite · Tailwind CSS

El objetivo

La landing page de un hotel ficticio en Bariloche, hecha para practicar maquetado responsive, accesibilidad e interactividad. Empezó con HTML y JavaScript puro, y después la migré a React con Vite.

Qué hace

  • Dos carruseles con reproducción automática que se pausan al pasar el mouse o al usar el teclado.
  • Página de habitaciones con foto, superficie, capacidad, tipo de cama y comodidades de cada una.
  • Ventana modal con la foto de cada habitación.
  • Formulario de reserva que no deja elegir fechas pasadas ni un check-out anterior al check-in, y que llega con la habitación ya elegida desde su página.
  • Mapa de ubicación y bloques que aparecen al hacer scroll.

Decisiones técnicas

  • Sin librerías de interfaz: los dos carruseles usan un único componente reutilizable hecho a mano, en vez de una librería tipo Swiper.
  • Elementos nativos: la ventana de cada habitación usa el elemento <dialog>, sin librerías de modales.
  • Animaciones accesibles: la aparición al hacer scroll usa IntersectionObserver y se desactiva con "reducir animaciones".
  • Tailwind compilado: Tailwind CSS se compila en el build con su plugin de Vite, y los colores de la marca se definen en un solo lugar.

Qué mejoraría

Conectar los formularios de contacto y reserva a un backend real, que hoy solo muestran una confirmación en pantalla.
